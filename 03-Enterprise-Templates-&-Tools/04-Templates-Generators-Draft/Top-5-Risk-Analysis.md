This template uses the PMI "Interest vs. Influence" grid to tailor communication.

### Stakeholder Communication Plan (PMI Framework)

| Stakeholder Group | Interest (H/M/L) | Influence (H/M/L) | Strategy (Keep Satisfied/Manage Closely) | Information Needed | Format | Frequency |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Executive Sponsor** | High | High | **Manage Closely** | Status on **Risk, Budget, Milestones** | 1-page Summary Report | Weekly (Email) |
| **Development Team** | High | Low | **Keep Informed** | Feature specifications, technical issues | Daily Standup, Kanban Board | Daily |
| **External Regulator** | Low | High | **Keep Satisfied** | Compliance Updates, Design Sign-offs | Formal Document Review | Monthly |
| **End Users** | Medium | Low | **Keep Informed** | Training schedules, new feature release notes | Newsletter, Training Sessions | Bi-Weekly |

### Develop a Change Request Form and Process

We can create a robust, standardized **Change Request Form (CRF)** and define the formal process for submitting, reviewing, and approving changes. This is absolutely critical for maintaining scope control in any formalized methodology (Waterfall, PRINCE2).

Would you like to generate an interactive **Change Request Form** template now? This form will include fields for impact analysis (cost, schedule, risk) before any change is approved.


That's an excellent choice. A formal **Change Request Form (CRF)** is the bedrock of project control. It ensures that every deviation from the baseline is documented, analyzed for impact, and formally approved. This prevents the dreaded "scope creep."

I've created an interactive **Change Request Form** that guides the requester through the essential steps of impact analysis (schedule, cost, and risk), ensuring your Change Control Board (CCB) has all the data needed for a rapid and informed decision.

The interactive application: http://googleusercontent.com/immersive_entry_chip/0

This form provides a structured process:

1.  **Request:** Fill in the title, description, and consequences of not approving the change.
2.  **Analysis:** The Project Manager scores the change based on **Schedule, Cost, and Risk Impact** (1-5 scale). The overall score is calculated automatically to signal immediate severity.
3.  **Mitigation:** Outline how the team will handle the inevitable impacts.
4.  **Decision:** Space is provided for the **Change Control Board (CCB)** to record their decision and rationale.
